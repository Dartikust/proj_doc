# Реестр договоров — первый прототип

Flask-сервис: загрузка PDF/DOCX → извлечение текста → номер, дата, стороны, сумма → SQLite → реестр и карточка документа.

План всего проекта и четырёх показов: [PIPELINE.md](PIPELINE.md).

## Настройки в .env

Файл `.env` находится рядом с `app.py` в `C:\Project` и автоматически читается при запуске. В Git включается только образец `.env.example`. Для нового компьютера скопируйте его: `Copy-Item .env.example .env`.

| Настройка | Назначение | По умолчанию |
|---|---|---|
| `APP_HOST`, `APP_PORT` | Адрес и порт для `python app.py` / `python site.py` | `127.0.0.1`, `5000` |
| `APP_DEBUG` | Режим отладки | `false` |
| `SECRET_KEY` | Ключ подписи сессии | Если пусто — используется `instance/secret.key` |
| `DATABASE`, `UPLOAD_FOLDER` | Путь к SQLite и папке оригиналов | `instance/contracts.sqlite3`, `instance/uploads` |
| `MAX_UPLOAD_MB` | Лимит размера запроса загрузки в МБ | `10` |
| `SEARCH_MODEL_DIR` | Папка скачанной модели | `instance/models` |
| `SEARCH_MIN_SCORE` | Порог сходства для поиска | `0.3` |
| `DOCUMENTS_PAGE_SIZE` | Документов на странице | `25` |

Относительные пути отсчитываются от папки проекта независимо от текущей папки терминала. Приоритет: настройки по умолчанию → `.env` → переменные окружения → конфигурация, переданная в `create_app()` (например, в тестах). Изменения применяются после перезапуска сервера.

Для Waitress параметры `--host` и `--port` задаются в команде запуска; остальные настройки приложения читаются из `.env`. Ключ нельзя публиковать вместе с кодом. API-ключи для текущего проекта не нужны: семантический поиск локальный.

## Быстрый запуск в Windows / PowerShell

В этой папке уже настроено новое окружение `.venv`. Старое `venv` осталось на месте, но оно ссылается на Python с другого компьютера.

```powershell
cd C:\Project
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5000. Нажмите «Скачать учебный договор», затем загрузите его через форму. Появятся реквизиты и исходный текст. Вернитесь в реестр: запись сохранена.

Отдельная страница [«Все документы»](http://127.0.0.1:5000/documents) содержит сортировку по дате заключения, сумме, заказчику и исполнителю. Можно выбрать оба направления; пустые значения всегда остаются в конце. Есть постраничный вывод по 25 документов.

Если сервер уже запущен, повторно запускать его не нужно. Остановить процесс в терминале можно `Ctrl+C`.

## Установка на другом компьютере

Нужен обычный CPython 3.12+ с `pip`. Для Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m scripts.prepare_search
.\.venv\Scripts\python.exe app.py
```

Не переносите виртуальное окружение между компьютерами: создавайте его заново. Некоторые сборки Python, например MSYS2, используют `.venv/bin` вместо `.venv/Scripts`.

Проверенные версии всех установленных пакетов находятся в `requirements-lock.txt`; для воспроизведения текущего окружения можно установить зависимости из него.

## Данные и проверки

```powershell
.\.venv\Scripts\python.exe -m scripts.generate_dataset
.\.venv\Scripts\python.exe -m scripts.evaluate
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Генератор создаёт 12 вымышленных договоров: три вида оформления, числовые и словесные даты, отвлекающие суммы аванса. Повторная генерация обновляет эти же учебные примеры. `data/synthetic/expected.json` содержит ожидаемые значения.

Чтобы проверить новую размеченную выборку: `python -m scripts.evaluate --dataset путь_к_папке`. В ней должны лежать документы и `expected.json` той же структуры.

## Поиск по смыслу

Поиск выполняется локальной многоязычной моделью `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` через FastEmbed / ONNX Runtime. Она превращает запрос и фрагменты договора в векторы; близость измеряется косинусным сходством. Это поиск с помощью нейросетевой модели, отдельно от RegEx-парсера реквизитов. Описание модели: [model card](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2); запуск через [FastEmbed](https://qdrant.github.io/fastembed/Getting%20Started/).

Однократная подготовка на новом компьютере (интернет нужен для скачивания модели размером около 220 МБ):

```powershell
.\.venv\Scripts\python.exe -m scripts.prepare_search
```

В текущей папке модель уже подготовлена. Веб-приложение загружает её только из локального кэша. Тексты договоров и запросы не отправляются во внешний API. Если модель отсутствует, страница сообщает, что поиск недоступен; обычный список и сортировка работают.

Индекс хранится в таблице `document_search_index` той же SQLite-базы. Абзацы индексируются отдельно; длинные абзацы делятся на окна по 40 слов с перекрытием 10. Реквизиты индексируются отдельно. Результат документа — максимальное сходство одного фрагмента с запросом. В выдаче виден этот фрагмент. Новые документы индексируются при первом поиске; при изменении текста/реквизитов индекс обновляется по хешу. Предварительно индексировать все документы можно командой подготовки.

По умолчанию поиск сортирует по сходству; найденные документы можно пересортировать по любому реквизиту. Порог сходства `SEARCH_MIN_SCORE=0.3` — исходная настройка для прототипа, её нужно оценить на вашей выборке. Сходство не является вероятностью правильного ответа. Поиск не интерпретирует условия вроде «сумма больше 100 тысяч» как строгие фильтры и не отвечает на вопросы — он возвращает документы.

Проверки реальной модели с русскими перефразированиями и длинным текстом:

```powershell
$env:RUN_SEMANTIC_MODEL_TESTS = '1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверки используют временную базу. Обычный запуск тестов пропускает два теста реальной модели, чтобы не требовать скачанного кэша на каждом компьютере.

## Где что находится

- `app.py` — веб-приложение. `site.py` оставлен совместимым запускателем.
- `contracts/readers.py` — чтение PDF и DOCX; `extractor.py` — правила извлечения.
- `contracts/pipeline.py` — цепочка чтения, нормализации, извлечения.
- `contracts/storage.py` — SQLite.
- `contracts/search.py` — семантический поиск и кэш векторов; `templates/documents.html` — список с поиском и сортировкой.
- `instance/models/` — локальные веса модели поиска, не включаются в Git.
- `instance/contracts.sqlite3` — сохранённый реестр; `instance/uploads/` — оригиналы; `instance/secret.key` — локальный ключ сессии. Каталог не включается в Git.
- `PIPELINE.md` — план проекта, схема, показы и следующие шаги.
- Файлы `main.c`, `scheduler.c`, `scheduler.h` относятся к отдельной задаче и не участвуют в сервисе.

## Ограничения и следующий шаг

Это локальный прототип, публичный хостинг ещё не настроен. PDF должен иметь текстовый слой: `pypdf` не выполняет OCR ([документация](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)). DOCX читается библиотекой `python-docx` ([документация](https://python-docx.readthedocs.io/en/latest/index.html)).

Парсер поддерживает явные подписи и часть типовых преамбул, сумму цифрами в рублях. Стороны представлены двумя отдельными полями. Неизвестные значения остаются пустыми. Исправление значений, OCR и авторизация ещё не реализованы. Семантический поиск и сортировка работают на отдельной странице.

Первое полезное улучшение — независимый датасет и ручное исправление полей. Затем можно решить по ошибкам, нужны ли Natasha/spaCy.

Для запуска через WSGI-сервер на Windows уже установлен Waitress:

```powershell
.\.venv\Scripts\waitress-serve.exe --host=127.0.0.1 --port=5000 --call app:create_app
```

Это локальный запуск. Подготовка публичного хостинга описана в `PIPELINE.md`.
