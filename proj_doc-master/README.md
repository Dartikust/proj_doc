# Реестр договоров — первый прототип

Flask-сервис: загрузка PDF/DOCX → извлечение текста → номер, дата, стороны, сумма → SQLite → реестр и карточка документа.

План всего проекта и четырёх показов: [PIPELINE.md](PIPELINE.md).

## Быстрый запуск в Windows / PowerShell

В этой папке уже настроено новое окружение `.venv`. Старое `venv` осталось на месте, но оно ссылается на Python с другого компьютера.

```powershell
cd C:\Project
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5000. Нажмите «Скачать учебный договор», затем загрузите его через форму. Появятся реквизиты и исходный текст. Вернитесь в реестр: запись сохранена.

Если сервер уже запущен, повторно запускать его не нужно. Остановить процесс в терминале можно `Ctrl+C`.

## Установка на другом компьютере

Нужен обычный CPython 3.12+ с `pip`. Для Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Не переносите виртуальное окружение между компьютерами: создавайте его заново. Некоторые сборки Python, например MSYS2, используют `.venv/bin` вместо `.venv/Scripts`.

Проверенные версии всех установленных пакетов находятся в `requirements-lock.txt`; для воспроизведения текущего окружения можно установить зависимости из него.

## Данные и проверки

```powershell
.\.venv\Scripts\python.exe -m scripts.generate_dataset
.\.venv\Scripts\python.exe -m scripts.evaluate
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Генератор создаёт 12 вымышленных договоров: три вида оформления, числовые и словесные даты, отвлекающие суммы аванса. Повторная генерация обновляет эти же учебные примеры. `data/synthetic/expected.json` содержит ожидаемые значения.

Чтобы проверить новую размеченную выборку: `python -m scripts.evaluate --dataset путь_к_папке`. В ней должны лежать документы и `expected.json` той же структуры.

## Где что находится

- `app.py` — веб-приложение. `site.py` оставлен совместимым запускателем.
- `contracts/readers.py` — чтение PDF и DOCX; `extractor.py` — правила извлечения.
- `contracts/pipeline.py` — цепочка чтения, нормализации, извлечения.
- `contracts/storage.py` — SQLite.
- `instance/contracts.sqlite3` — сохранённый реестр; `instance/uploads/` — оригиналы; `instance/secret.key` — локальный ключ сессии. Каталог не включается в Git.
- `PIPELINE.md` — план проекта, схема, показы и следующие шаги.
- Файлы `main.c`, `scheduler.c`, `scheduler.h` относятся к отдельной задаче и не участвуют в сервисе.

## Ограничения и следующий шаг

Это локальный прототип, публичный хостинг ещё не настроен. PDF должен иметь текстовый слой: `pypdf` не выполняет OCR ([документация](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)). DOCX читается библиотекой `python-docx` ([документация](https://python-docx.readthedocs.io/en/latest/index.html)).

Парсер поддерживает явные подписи и часть типовых преамбул, сумму цифрами в рублях. Стороны представлены двумя отдельными полями. Неизвестные значения остаются пустыми. Исправление значений, поиск, OCR и авторизация ещё не реализованы.

Первое полезное улучшение — независимый датасет и ручное исправление полей. Затем можно решить по ошибкам, нужны ли Natasha/spaCy.

Для запуска через WSGI-сервер на Windows уже установлен Waitress:

```powershell
.\.venv\Scripts\waitress-serve.exe --host=127.0.0.1 --port=5000 --call app:create_app
```

Это локальный запуск. Подготовка публичного хостинга описана в `PIPELINE.md`.
